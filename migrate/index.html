Data Migration Tool

Copy your data in from an S3-compatible bucket or straight off an SFTP server. The transfer runs on our infrastructure, not yours: fill in a short form, hit start, and close the tab. It keeps going overnight, across reconnects, and well past the multi-terabyte mark without you writing a single transfer script.

  • S3-compatible sources: AWS S3, Wasabi, Backblaze B2, Cloudflare R2, DigitalOcean Spaces, MinIO, self-hosted Ceph. A whole bucket, one prefix, or a single object.
  • SFTP sources: any Linux server reachable over the internet, by password or SSH key. Useful for HPC scratch and sequencer drop folders.
  • Roughly 1.5 hours per TiB: parallel and resumable, with a live log and progress you can watch or walk away from.
  • Credentials are never stored: source secrets pass to the worker once and are discarded.

Find it under Storage → Migrate in the console.

Migration questions

How do I move my data from AWS S3 to Carolina Cloud?

Use the Data Migration Tool under Storage → Migrate in the console. It copies from any S3-compatible bucket (AWS S3, Wasabi, Backblaze B2, Cloudflare R2, DigitalOcean Spaces, MinIO, Ceph) or an SFTP server, runs on our infrastructure, and is parallel and resumable at roughly 1.5 hours per TiB.

Do I have to rewrite code to leave AWS?

Usually not. Object storage is S3-compatible, so existing AWS CLI, boto3, rclone and s3cmd usage keeps working with one endpoint change.

Are my source credentials stored?

No. Source secrets pass to the worker once and are discarded, never written to our database. For SFTP we generate the keypair, so you paste one public key into authorized_keys.

Are there migration credits?

Yes. Email hello@carolinacloud.io with your AWS bill and a sketch of the workload, and we will reply with a like-for-like quote and a migration plan.
